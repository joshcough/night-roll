## PROPOSED — tooling: composition mode (Josh, 2026-08-14)

Josh's framing: the analysis sessions generate melodic ideas, and he wants
to flip straight into writing one without leaving bed. He asked for "the
full ability to create new files and put in notes on both the roll and the
score, set the tempo, add new instruments — everything you'd expect from a
modern music editor," accepting finger entry as the input method.

### What exists today (verified in index.html this session)

Pencil/Erase are real and undocumented anywhere except the ? help line.
Edit reveals them; a duration segment (16th / 8th / 1/4 / 1/2) appears with
Pencil. Pencil taps the roll grid → pushes `{t, d, p, v: 80, added: true}`
onto the SELECTED track, snapped to the chosen duration. Erase flags a
tapped note `gone`. Both write through to `song.rawNotes` so chop stays
consistent, and `saveEdits()` persists added/removed to localStorage per
song.

### The gaps between that and what Josh asked for

1. **Roll only.** `onTap` returns into `scoreTap(pos)` before reaching the
   pencil branch, so the score never accepts note entry.
2. **No new song.** Every path assumes a loaded .mid. No blank-canvas
   creation, no track creation — `selTrack` only ever moves among tracks
   that already exist (set at load, or by tapping a track row).
3. **No MIDI export.** Download serializes `.rollnotes` only. Notes penciled
   in live in localStorage and can leave the device by no route at all.
   For analysis scratch that's fine; for composition it means the work is
   trapped on one iPad.
4. **No tempo control.** Tempo comes from the loaded file's tempo map.
5. **Fixed velocity 80**, four durations, no rests/ties, no dotted values,
   no undo.

### Design questions for Josh before anything is built

- Score-side entry: same tap-to-place model, or note-value palette then tap
  a staff position? (Roll entry is pitch-continuous; the staff is not.)
- New song: how much does it ask for up front — tempo, meter, track count,
  instrument per track — versus defaults he edits after?
- Where do compositions live? `albums/compositions/` already exists and the
  Sync path knows how to commit to the repo; a new song has no repo path
  until it's named. Sync currently says "Local file — Copy/Download only."
- Is MIDI export the exit route (the NSF pipeline's MIDI writer in
  `tools/nsf/` is pure JS and could run in the page), or is a native
  Night Roll song format the better target?
